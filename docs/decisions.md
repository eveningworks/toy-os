# Decisions

A short, topic-indexed answer to "why does toy-os work this way?" for
the choices that come up again once code has grown around them.
`README.md`/`apps/README.md` cover architecture; this covers the
arguments.

**The entries live in [`docs/decisions/`](decisions/), split by area.**
This file is the INDEX over them, and it is GENERATED -- add an entry to
the right file in that directory and run `tools/gen_decisions_index.py`.
`tools/check_docs.py` fails the build if the index is stale, because an
index kept true by someone remembering is the exact shape of every
convention this project has had to delete.

**WRITE THE REASONING THERE, IN FULL.** Entries used to be pointers into
a changelog that held the real writeup; that changelog was closed in
August 2026 and deleted, and the entries that had leaned on it were the
ones left stranded. An entry that cannot be understood without opening
something else is not finished. Older entries still cite a commit for
implementation detail -- that is a "see also", and a new entry should
not need one.

**The bar for an entry:** it answers "why this way and not the obvious
way", and a future session would plausibly re-litigate it. What changed
goes in the commit message, how a mechanism works goes in a comment
beside the code, and what is broken goes in `docs/roadmap.md`.

If you are a Claude session or a contributor about to ask "wait, why is
this built this way instead of the more obvious way?" -- check here
first before re-litigating it from scratch.
